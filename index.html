01

Overview & Agenda

10 MIN

In this lab your team picks one real-world healthcare or life sciences challenge and builds a working AI data agent on Snowflake in 90 minutes, using Cortex Code (CoCo) as your build partner. There is no step-by-step script. You get the data, a clear goal and a set of business questions, and your team decides how to get there.

Kick-off · ~10 minDesign Thinking with CoCo: intro, ground rules, ideation
Build · ~70 minBuild time starts. Set up, load data, pick your track
Finish · ~20 minFreeze the build, test in CoWork, prep your pitch
Pitch · 90 sec per team90-second team pitches

AI functions turn free text into columns. Cortex Analyst answers the numbers questions, Cortex Search answers the text questions, and the agent combines both.

What you will learn

  • How to explore an unfamiliar dataset quickly with CoCo
  • How to apply Cortex AI functions (classify, extract, filter, summarize) to clinical and operational text in SQL
  • How a semantic view gives Cortex Analyst the business vocabulary for your tables
  • How Cortex Search makes notes, narratives and documents retrievable with citations
  • How a Cortex Agent picks the right tool, or both, for each question
  • How to put the agent in front of business users in Snowflake CoWork
All data is 100% synthetic

Every dataset was generated for this lab and modelled on real payer and life sciences schemas. It contains no real patient, member or PHI data. Each dataset also hides a pattern. Part of the challenge is getting your agent to find it.

Setup & Data Load

10 MIN

Setup has two steps, both run in a SQL worksheet as ACCOUNTADMIN. Step 3a runs once per account. Step 3b loads your team's track data from the public lab repo.

Step 3a: Common setup (run once)

In Snowsight, open a new SQL worksheet (+ → SQL File or Projects → Workspaces). Paste the block below and choose Run All. It creates the warehouse and database, connects the public GitHub repo, creates file formats, and enables cross-region inference so all Cortex models are available.

SQLsetup/00_common.sql · run as ACCOUNTADMIN · ~1 minute
USE ROLE ACCOUNTADMIN;

-- Compute for the lab (X-Small, auto-suspends after 2 minutes idle)
CREATE WAREHOUSE IF NOT EXISTS HCLS_LAB_WH
  WAREHOUSE_SIZE = 'XSMALL' AUTO_SUSPEND = 120 AUTO_RESUME = TRUE;
USE WAREHOUSE HCLS_LAB_WH;

-- One database for the lab; each track gets its own schema
CREATE DATABASE IF NOT EXISTS HCLS_LAB;
USE DATABASE HCLS_LAB;

-- Connect to the public lab GitHub repo (no credentials needed)
CREATE OR REPLACE API INTEGRATION HCLS_LAB_GIT_API
  API_PROVIDER = git_https_api
  API_ALLOWED_PREFIXES = ('https://github.com/sfc-gh-gkatireddy')
  ENABLED = TRUE;

CREATE OR REPLACE GIT REPOSITORY HCLS_LAB.PUBLIC.HCLS_LAB_REPO
  API_INTEGRATION = HCLS_LAB_GIT_API
  ORIGIN = 'https://github.com/sfc-gh-gkatireddy/hcls-innovation-lab.git';
ALTER GIT REPOSITORY HCLS_LAB.PUBLIC.HCLS_LAB_REPO FETCH;

-- File formats used by the loader scripts
CREATE OR REPLACE FILE FORMAT HCLS_LAB.PUBLIC.CSV_FORMAT
  TYPE = 'CSV' FIELD_OPTIONALLY_ENCLOSED_BY = '"' SKIP_HEADER = 1
  NULL_IF = ('') EMPTY_FIELD_AS_NULL = TRUE;
CREATE OR REPLACE FILE FORMAT HCLS_LAB.PUBLIC.TEXT_FORMAT
  TYPE = 'CSV' RECORD_DELIMITER = 'NONE' FIELD_DELIMITER = 'NONE';

-- Required: lets Cortex use models hosted in other regions
ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';

Step 3b: Load your track's data

Run the single line for your team's track. Each loader creates a schema, the tables, a stage, loads the CSVs from the repo, and returns row counts at the end. You can read any loader in the repo's setup/ folder, where every column is commented.

SQLRun ONE line, for your track · ~30 seconds
USE ROLE ACCOUNTADMIN; USE WAREHOUSE HCLS_LAB_WH;

-- P1 Claims Denial Triage
EXECUTE IMMEDIATE FROM @HCLS_LAB.PUBLIC.HCLS_LAB_REPO/branches/main/setup/load_p1_claims_denials.sql;

-- P2 HEDIS Care Gap Closure
EXECUTE IMMEDIATE FROM @HCLS_LAB.PUBLIC.HCLS_LAB_REPO/branches/main/setup/load_p2_hedis_gaps.sql;

-- L3 Commercial HCP 360 & Next Best Action
EXECUTE IMMEDIATE FROM @HCLS_LAB.PUBLIC.HCLS_LAB_REPO/branches/main/setup/load_l3_commercial_hcp360.sql;

-- L4 Real World Evidence: Treatment Patterns on OMOP
EXECUTE IMMEDIATE FROM @HCLS_LAB.PUBLIC.HCLS_LAB_REPO/branches/main/setup/load_l4_rwe_treatment_patterns.sql;
Run only one line at a time

Put your cursor on your track's line and run just that statement. Running several is harmless, because each loader only touches its own schema, but it takes longer.

Troubleshooting
  • "Git repository does not exist": Step 3a did not complete. Re-run it in full.
  • "No active warehouse": run USE WAREHOUSE HCLS_LAB_WH; and retry.
  • Model "not available in your region": the CORTEX_ENABLED_CROSS_REGION line in Step 3a did not run. Run it as ACCOUNTADMIN.
  • Insufficient privileges: switch your role to ACCOUNTADMIN (top-left user menu).

05

Build with CoCo

55 MIN

There are no copy-paste prompts in this lab. CoCo is your build partner: describe what you want in plain English, review what it proposes, and approve it. The guidance below works for every track.

How to work with CoCo

  • Explore before you build. Ask CoCo to describe the tables in your schema, how they join, and what the free-text columns look like. Five minutes here saves twenty later.
  • Give context, not just commands. Tell CoCo who the persona is and what business question you are answering. Point it at the exact schema, for example HCLS_LAB.P1_CLAIMS_DENIALS.
  • Plan, then build. For bigger steps such as the semantic view or the agent, ask CoCo for a plan first, agree on it, then let it execute.
  • One step at a time. Build and verify each layer (AI step → semantic view → search → agent) before moving to the next.
  • Review what it runs. CoCo shows SQL and DDL before executing. Read it and ask "why" if something looks off.
  • Test on a sample first. Run AI functions on LIMIT 20 rows, check the output, then run them on the full table.
  • When something fails, paste the error back to CoCo and ask it to fix the problem. Don't start over.

Suggested team roles

ROLEFOCUS

Keep it simple, then extend

A working agent that answers three questions well beats an ambitious one that answers none. If your agent is live with time to spare, try your track's stretch goal in the Track Briefs.

Names that help later

Create your semantic view, search service and agent inside your track's schema, with descriptive names. Clear tool descriptions in the agent (what each tool is for) make a big difference to how well it picks the right one.

06

Snowflake CoWork

10 MIN

Snowflake CoWork (formerly Snowflake Intelligence) is the chat interface where business users talk to your agent, with no SQL needed. Creating an agent and making it visible in CoWork are separate steps.

Step 6a: Register your agent

SQLAdd your agent to CoWork · replace the agent path with yours
USE ROLE ACCOUNTADMIN;

-- Creates the account-level CoWork object if it does not exist yet
CREATE SNOWFLAKE INTELLIGENCE IF NOT EXISTS SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT;

-- Register your agent so it shows up in CoWork
ALTER SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT
  ADD AGENT HCLS_LAB.<YOUR_TRACK_SCHEMA>.<YOUR_AGENT_NAME>;

-- Verify
SHOW AGENTS IN SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT;

You can also ask CoCo to do this for you.

Step 6b: Open your agent

Route 1: CoWork directly

  1. Go to ai.snowflake.com and sign in with the same account.
  2. Select your agent from the agent picker and start a conversation.

Route 2: from Snowsight (always works)

  1. Go to AI & ML → Agents and select your agent.
  2. Click Preview in Snowflake CoWork.

Step 6c: Test like a business user

  • Ask your track's business questions in plain English, the way the persona would.
  • Ask at least one combined question that needs numbers from Analyst and text from Search.
  • Expand the response to see which tool was used, the SQL generated and the passages retrieved. This "show your work" view is great pitch material.
  • If an answer is off, ask CoCo to improve the agent instructions, tool descriptions or semantic view, then test again.
Agent not listed in CoWork?

It is almost always registration, not a broken agent. Re-run the ADD AGENT statement and reload, or use Route 2.

From lab to production

Govern it with Horizon

Apply row access and masking policies so the same agent returns only what each role may see. This is essential for PHI.

Reuse your existing semantics

Business definitions already live in BI reports, dbt models and data dictionaries. Bring them into your semantic view so agent answers match the reports leadership already trusts.

Close the loop

Add custom tools, such as a stored procedure that creates a worklist or sends an alert, so the agent can act and not only answer.

Cleaning up (optional)

Your trial account keeps the lab objects. To remove them, run DROP DATABASE HCLS_LAB; and DROP WAREHOUSE HCLS_LAB_WH;.

P1 Claims Denial Triage Agent

Payer / Revenue Integrity

Health plans and providers lose billions to denied claims that are never worked, often because no one can quickly see why claims are denied or which ones are worth fighting.

Why it matters

19% of in-network marketplace claims are denied, yet under 1% are appealed.
About $57 to work one appeal, with a high overturn rate. The rework is large but hard to target.

Persona

Payment integrity / revenue cycle analyst who needs a prioritized worklist, not another static report.

Business questions your agent should answer

  • What are the top denial drivers by provider and category?
  • How many dollars are at risk from preventable denials?
  • Which providers show unusual denial patterns?
  • Which claims should we appeal first, and why?
  • What does our policy say about the top denial reason?

Data provided (synthetic)

TableWhat is in it
MEMBERS~2k members, plan and demographics
PROVIDERS~200 providers, specialty, network status
CLAIMS~20k claims with billed/paid amounts and CARC denial codes
DENIAL_NOTES~2,800 free-text adjudication and denial notes
Policy docs5 payer policy documents (PAYER_POLICIES)

The AI step

Classify denial note text as preventable vs. not preventable and assign a root-cause category (e.g. missing auth, coding error, eligibility).

Agent tools

  • Cortex Analyst on a claims and denials semantic view
  • Cortex Search on the parsed payer policy documents

Snowflake capabilities

AI_CLASSIFYAI_PARSE_DOCUMENTSemantic ViewCortex AnalystCortex SearchCortex AgentSnowflake CoWork

What done looks like

An agent that, in plain English, ranks the denials worth appealing and explains the root cause and the dollars behind each one.

Stretch goal

Have the agent draft an appeal letter for a top claim using AI_COMPLETE, citing the policy passage returned by Cortex Search.

P2 HEDIS Care Gap Closure from Clinical Notes

Payer / Quality and Stars

Quality teams employ armies of chart reviewers to find care that happened but never showed up in claims. That evidence sits in clinical notes, and finding it directly moves Star ratings and reimbursement.

Why it matters

Health systems using AI on notes have reported up to an 85% reduction in manual chart review effort.
Every gap closed lifts HEDIS measure rates, which feed Star ratings and quality bonuses.

Persona

Quality / Stars program manager who needs a ranked worklist so reviewers only look at charts that will close a gap.

Business questions your agent should answer

  • Which open care gaps have supporting evidence in the notes?
  • What is the potential gap closure lift by measure?
  • Which members should reviewers look at first?
  • Which measures have the biggest documentation gap?
  • Show me the note passage that closes this member's gap.

Data provided (synthetic)

TableWhat is in it
MEMBERS~2k members with demographics and plan
MEASURE_GAPS~4.8k open/closed gaps (e.g. HbA1c control, breast cancer screening, colorectal screening)
CLAIMS~15k claims with procedure and diagnosis codes
VISIT_NOTES~2,800 free-text clinical visit notes

The AI step

Extract structured evidence from notes (test performed, date, result) and match it to open gaps. Use AI_FILTER to quickly narrow to notes that mention a measure.

Agent tools

  • Cortex Analyst on a members, gaps and evidence semantic view
  • Cortex Search on the visit notes, to show the supporting passage

Snowflake capabilities

AI_EXTRACTAI_FILTERSemantic ViewCortex AnalystCortex SearchCortex AgentSnowflake CoWork

What done looks like

A ranked reviewer worklist of gaps likely closable from chart evidence, plus an agent that explains the evidence it found for any member.

Stretch goal

Estimate the impact on measure rates and the Star rating if the identified gaps are closed.

L3 Commercial HCP 360 and Next Best Action

Life Sciences / Commercial

Brand teams have more commercial data than ever, but still can't quickly say why a brand is slowing in a territory or which doctors a rep should see next. The numbers live in prescription data; the reasons live in what doctors tell reps.

Why it matters

Commercial / HCP 360 is one of the most common data and AI themes across top pharma accounts.
Turning rep notes into objection and competitor signals lets brand teams react in weeks, not quarters.

Persona

Brand manager / commercial excellence lead for Glucavia, a once-weekly GLP-1 for type 2 diabetes.

L4 Real World Evidence: Treatment Patterns on OMOP

Life Sciences / Medical Affairs and RWE

Real-world data shows how drugs perform outside trials: who gets them, how long patients stay on therapy, and why they stop. Structured data shows that patients stop; the why is usually only in clinical notes.

Why it matters

Real World Evidence is a top data priority across life sciences, feeding label expansion, HEOR and payer value stories.
Poor persistence erodes real-world outcomes and brand value; knowing why patients stop points to fixable causes.

Persona

RWE / medical affairs scientist for Glucavia, explaining real-world persistence and outcomes to brand and clinical teams.

Business questions your agent should answer

  • Who starts each add-on therapy, and what do they look like?
  • What is 6-month persistence by drug and age group?
  • How much do HbA1c and BMI improve on each drug?
  • Why are patients stopping Glucavia, and when?
  • Show me notes that explain it.

The AI step

Classify notes by discontinuation reason and extract details such as side effects, switch-to drug or titration approach, then join them back to therapy episodes.

Agent tools

  • Cortex Analyst on a patients, therapy episodes and outcomes semantic view
  • Cortex Search on the clinical notes, to quote patient evidence
